## Phase 1 — Full-page screenshot, no new permission by default

Goal: press a shortcut, get one PNG of the whole page, saved or copied.

Approach A (default, no permission): **stitch**

- Content script injected on demand, same posture as today: `activeTab` +
  `scripting`, nothing persistent.
- Read `document.documentElement.scrollHeight`, viewport height, device pixel
  ratio.
- Loop: `window.scrollTo(0, y)`, wait for two animation frames plus a settle
  delay, `chrome.tabs.captureVisibleTab`.
- Compose on an `OffscreenCanvas` in the offscreen document, crop the last frame
  to the real remaining height, encode `image/png`.
- Cap: 20 000 px tall, 40 frames. Past that, refuse and say why.
- Sticky/fixed elements: hide them after the first frame by injecting
  `[data-mdz-sticky]{visibility:hidden}` on elements whose computed position is
  `fixed` or `sticky`, restore after. Prevents the repeated-header band.

Approach B (opt-in, `debugger`): single `Page.captureScreenshot` with
`captureBeyondViewport: true` and `clip`. Exact, one frame, no scroll flicker.
Gated behind `chrome.permissions.request({permissions:["debugger"]})` from the
options page. Also unlocks `Emulation.setEmulatedMedia` for Phase 3.

Files:

- `apps/extension/src/screenshot.ts` — preflight (measure), plan (frame count),
  stitch (pure function over frames, unit-testable)
- `apps/extension/src/background.ts` — orchestration, offscreen document
  lifecycle, `chrome.offscreen` (needs `offscreen` permission — **decide**: it is
  a normal permission, not host permission, and it does not add a warning that
  hurts. Alternative without it: composite in a tab page. Recommend the tab page,
  keeps permissions at five.)
- `apps/extension/src/tabs/preview.tsx` — "Screenshot" button, then Download PNG
- `apps/extension/test/screenshot.test.ts` — pure stitch function: 3 overlapping
  frames of known solid colors produce a PNG-sized canvas of the right height and
  the right seams

Verify: real build both targets, manifest unchanged at five permissions, test
suite green, then a manual check against a long local fixture page.

Commit: `feat(ext): capture a full page by stitching visible frames`

## Phase 2 — Copy for Figma

Goal: one button puts three flavours on the clipboard. Figma takes the HTML,
everything else takes the PNG or the Markdown.

```ts
await navigator.clipboard.write([new ClipboardItem({
  "text/html":  new Blob([figmaHtml], { type: "text/html" }),
  "text/plain": new Blob([markdown],  { type: "text/plain" }),
  "image/png":  new Blob([png],       { type: "image/png" })
})]);
```

`figmaHtml` rules, all in one file, all unit-testable:

- Walk the live DOM in document order.
- Skip: zero-size, `display:none`, `visibility:hidden`, `opacity:0`, `script`,
  `style`, `link`, `meta`, `noscript`.
- Every kept element gets inline `position:absolute; left; top; width; height`
  from `getBoundingClientRect()` relative to the root.
- Carried styles: `background-color`, `background-image` (gradient only),
  `color`, `font-family`, `font-size`, `font-weight`, `font-style`,
  `line-height`, `letter-spacing`, `text-align`, `text-decoration`,
  `border` (width, style, color, radius), `box-shadow`, `opacity`,
  `transform` (translate/scale only).
- Text nodes stay text; no word splitting.
- `<img>` and `background-image: url()` become data URIs when same-origin or
  already a data URI. Cross-origin images: keep the absolute URL and accept the
  gap, do not proxy (that would be a network call, and the pitch says none).
- `<svg>` inlined as-is, capped at 400 KB each.
- Budgets: 5 000 nodes, 6 MB of HTML. Over budget: drop to the nearest landmark
  section (`main`, `article`, `section` with the largest area) and say so in the
  toast.

Files:

- `apps/extension/src/figma-snapshot.ts`
- `apps/extension/test/figma-snapshot.test.ts` — pinned fixtures: absolute
  positions on nested boxes, hidden node dropped, gradient preserved, data URI
  image, budget fallback
- `apps/extension/src/tabs/preview.tsx` — "Copy for Figma" button

Verify: build, tests green, manual paste into Figma desktop against a real page.

Commit: `feat(ext): copy the page as figma-ready inline html`

## Phase 3 — Theme simulation

Two modes, one toggle in the popup and one in the preview tab.

- **Real emulation** (`debugger`, opt-in): `Emulation.setEmulatedMedia` with
  `prefers-color-scheme: dark|light`. The site's own theme, no distortion.
- **Fallback filter** (no permission): inject a stylesheet
  `html{filter:invert(1) hue-rotate(180deg)}` plus a counter-invert rule for
  `img, video, canvas, picture, [style*="background-image"]`. Instant, anywhere,
  visibly approximate — label it "Approximate" in the UI so nobody mistakes it
  for the real thing.

State is per tab, held in `chrome.storage.session` under `mdzTheme:<tabId>`,
applied with `chrome.scripting.insertCSS` / `removeCSS`, cleared on
`tabs.onRemoved`. No persistence across reloads.

Files: `apps/extension/src/theme.ts`, `apps/extension/test/theme.test.ts`
(the CSS text builder is pure), popup and preview wiring.

Verify: build, tests, manual check on three real sites with real dark themes.

Commit: `feat(ext): simulate dark and light mode per tab`

## Phase 4 — DESIGN.md as a product surface

Two deliverables that must not be confused:

**4a. This repo's own design spec** — `DESIGN.md` at root, Google spec format,
YAML tokens + prose in the canonical section order. Lint with
`npx -y @google/design.md lint DESIGN.md`. Export `tokens.json` (DTCG) and
`tokens.tailwind.json`. Screenshots of popup, preview, options into
`docs/design/`. One palette, one typography scale, one spacing scale, covering
the extension UI and (later) the site.

**4b. Feature: an AI drives Chrome and writes a DESIGN.md for any site.** This is
where the MCP question gets settled honestly:

- `mdz-mcp` today is a stdio process with no browser access. It cannot drive
  Chrome and will not pretend to.
- The realistic shape: an agent already driving Chrome (Playwright MCP or
  equivalent) visits the site, reads computed styles, and writes `DESIGN.md`
  itself. `mdz` contributes what it is good at — `mdz_outline` to pick the
  sections worth sampling, and a new `mdz_design_tokens` tool that takes a DOM
  snapshot and returns a token draft (`colors`, `typography`, `spacing`,
  `rounded`) in the exact YAML shape `DESIGN.md` wants.
- The extension contributes the same thing from the active tab: "Extract design
  tokens" button, downloadable `DESIGN.md` + `tokens.json` + PNG contact sheet.

So the three export paths the user asked for become: **download** (files),
**copy** (clipboard), **MCP** (`mdz_design_tokens` over stdio). No new server, no
native messaging host, no socket daemon.

Files:

- `DESIGN.md`, `docs/design/*.png`, `tokens.json`
- `packages/core/src/design-tokens.ts` + test — DOM in, token draft out
- `apps/mcp/src/server.ts` — register `mdz_design_tokens`
- `apps/extension/src/tabs/preview.tsx` — Download DESIGN.md

Verify: `npx @google/design.md lint DESIGN.md` clean or warnings understood,
DTCG export parses, MCP tool covered by a test, extension build green.

Commit split: `docs: add design tokens and spec`, `feat(core): derive design
tokens from a dom`, `feat(mcp): expose design token extraction`,
`feat(ext): export design tokens from the active tab`
